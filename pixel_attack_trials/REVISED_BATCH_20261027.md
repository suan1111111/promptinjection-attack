# 第二批七种形式

统一原图：Soft-Prompts-Go-Hard 的 clean_images/0.png；严格配对 instruction_data/0/Attack/dataset.csv，目标取 injection 列，仍为字面占位符 <maliciousurl>。冻结本地 Qwen2.5-VL-3B，NF4/BF16。原图、CSV 和第一批结果不覆盖。

先进行每种形式一次真实更新、导出和生成的短程检查。全部通过才启动正式串行队列；失败时驱动器停止，不把失败当作成功。

正式设置：七种形式各 1000 次更新，每次平均四个训练问题的梯度；前40题训练，保留原有数据划分，导出后测试10道 test 问题，512 token，独立上下文。每50步保存图片和日志。相比第一批每形式300次问答处理，本批为4000次。此设置仍不能保证行为成功。

变更：
- 低频：保留系数梯度的相对大小，按逆DCT后的空间最大变化归一化步长。
- 稀疏：根据当前梯度估计的损失收益选择位置，避免只按历史扰动幅度选位置；步长4/255，预算仍32/255、256个位置。这是待实测的新更新规则，不是原论文复现。
- 花形：90×90包围框，实际轮廓面积接近56×56矩形贴片，允许255/255覆盖。此次检验不规则轮廓，不声称真实自然花朵外观。
- 固定/随机贴片：支持四问题梯度累积；随机贴片每个问题分别抽位置。最终主要评估仍为右上角位置，不能据此声称位置泛化。
- 旧像素更新规则保留为 legacy，新规则显式 revised；检查点记录新版本，避免混用。

六组约束测试及两组贴片测试通过。短程和正式训练状态以对应输出目录中的 status.json 为准。所有生成回答保存在各任务 evaluation.json，不能只凭训练结束或loss下降认定成功。
