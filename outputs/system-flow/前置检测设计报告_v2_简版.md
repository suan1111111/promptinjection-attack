# 前置检测实现方案

## 一、实现目标

利用已经总结好的专属模式，对输入图片进行快速匹配。每个模式所需的特征、判断规则和阈值已经确定，本部分主要通过共享计算结果、按需提取和调整执行过程，提高匹配效率。

## 二、前置检测如何运行

1. **登记专属模式的计算需求。** 记录每个模式需要哪些特征，以及提取这些特征需要哪些计算步骤和中间结果，建立计算依赖关系。
2. **建立共享特征缓存。** OCR、梯度窗口、局部熵候选区域等结果，在输入和计算配置一致时只计算一次，供多个模式使用。已有的缓存继续复用，尚未打通的部分逐步统一。
3. **按需安排计算与匹配。** 根据当前检查的需要，只提取所需特征；已有结果直接复用，其他特征等后续需要时再计算。某个模式具备判断条件后，及时进行匹配，不必等待另一个模式的整套计算完成。
4. **完成分流。** 高置信度匹配已知模式的图片，按既定匹配优先级进入第二步的专属检测路径；所有模式均未匹配时，补齐剩余图片特征，进入第一步的通用候选筛选。前置命中只表示匹配已知模式，不直接确认攻击成立。

## 三、用户如何通过交互改进执行过程

新增专属模式或优化已有策略时，通过以下过程形成调整闭环：

1. **分析计算关系与执行开销。** 系统以可视化方式关联展示各模式所需的特征、计算依赖、共享结果和执行情况，帮助用户发现重复计算、不必要的连带计算或可能过早执行的计算。
2. **提出执行调整。** 用户据此调整计算结果的共享方式、特征提取的先后顺序和模式检查顺序。也可以将模式的计算过程分阶段安排，使已具备所需特征的模式及时判断，其他计算在后续仍有需要时再执行。
3. **形成可执行的候选策略。** 系统检查共享结果是否兼容、计算依赖是否满足，以及模式判断和分流要求是否保留，将调整组织成完整的候选执行策略。不符合要求的部分反馈给用户修订。
4. **比较效果并反馈原因。** 系统使用具有足够检测记录的历史样本比较原策略和候选策略，展示哪些计算减少、哪些增加、整体时间及匹配结果如何变化，并将这些变化关联到具体执行环节，供用户判断调整是否有效。
5. **修订或应用。** 用户根据比较结果继续修改、撤销调整，或采用有效策略。采用后由系统自动处理新图片，后续执行记录可用于下一轮优化。

模式顺序与特征提取顺序需要协调调整，不能相互独立。全过程保留模式所需的特征、计算定义、判断规则和阈值，不以未知结果代替实际检查，也不预先假定某类图片更容易命中。历史记录不足时需补测，效率改善通过比较验证。

例如，模式 A 需要 OCR 和梯度，模式 B 需要 OCR 和文字规则。用户可以提出在共享 OCR 结果后，先完成 B 的检查，将梯度计算推迟到仍需检查 A 时。系统检查该安排是否符合依赖和分流要求，再通过样本比较判断它是否减少了整批图片的计算开销。

## 四、需要实现的主要功能

| 功能 | 要做什么 |
| --- | --- |
| 计算依赖管理 | 描述特征的输入、计算步骤、中间结果及所属模式 |
| 按需提取与共享缓存 | 拆分现有提取入口，只执行需要的计算组，复用兼容结果 |
| 自动执行调度 | 根据依赖和策略安排计算，及时判断模式并完成分流 |
| 可视化分析与策略调整 | 关联呈现计算依赖和执行情况，支持调整共享方式、特征提取顺序及模式检查顺序 |
| 方案比较与应用 | 使用历史样本检查调整效果，保存并应用有效策略 |

用户在界面上调整计算共享方式和执行顺序，系统检查调整是否可行，并用已有样本比较效果，再将有效方案用于后续检测。
