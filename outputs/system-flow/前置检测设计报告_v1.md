# 基于计算复用与可视交互的前置检测设计报告

版本：v1（方案稿）  
日期：2026年10月28日

## 一、设计背景与目标

系统在案例积累和攻击模式总结阶段，已经确定各专属模式所需的图片特征、判断规则和命中阈值。新图片进入系统后，前置入口调用这些已确定的方法，尝试匹配已知攻击模式。高置信度匹配的图片进入第二步的专属检测路径；所有模式均未高置信度匹配时，补齐第一步所需的剩余图片特征，进入候选筛选。

随着专属模式增加，不同模式可能使用同一种计算结果，也可能使用由同一中间结果派生的不同特征。如果将每个模式作为不可拆分的整体依次运行，就可能出现重复计算、提取无关特征，以及在图片匹配成功之前过早执行昂贵计算等情况。

本设计的目标是：**在保持专属模式检测定义的前提下，通过计算结果复用和执行过程重组，减少完成前置匹配所需的计算时间，并利用可视化交互帮助用户理解、提出和检查这些调整。**

用户不需要逐张辨认攻击类型，也不需要在前置入口重新选择每个模式使用哪些特征。系统负责自动执行检测；用户主要在新增模式或调整策略时，对执行结构进行分析和修改。

## 二、总体思路

### 2.1 区分模式定义与执行方式

模式定义包括所需特征、特征计算方法、判断规则和阈值。执行方式描述这些特征何时计算、从哪里取得结果，以及何时执行模式判断。

本设计调整执行方式，保留模式定义。模式仍然在逻辑上独立，但计算过程可以共享和交错安排。

| 保持不变的内容 | 可以调整的内容 |
| --- | --- |
| 模式所需的特征及其定义 | 兼容计算结果的共享方式 |
| 特征计算的算法和参数 | 计算组的按需调用方式 |
| 模式判断规则和命中阈值 | 计算步骤的先后顺序与执行阶段 |
| 完成判断所需的证据要求 | 满足既定逻辑时的检查停止位置 |

### 2.2 将依赖定义为计算结果的使用关系

以实际代码为依据，建立“计算步骤—中间结果—特征—模式”的关系。

例如，梯度计算产生窗口统计和选中窗口。这些结果既可用于高梯度区域比例，也可结合 OCR 文字区域计算二者的重合程度。两个模式使用的最终特征不同，但其上游计算存在可复用部分。

这种关系表示“某项计算需要什么结果”，不等同于特征之间的统计相关性。新模式依赖的通常是某个共享中间结果，而不是另一个模式的完整检测过程或检测结论。

## 三、现有代码基础

项目已实现 OCR 数值、文字规则、跨区域文字组合、梯度、频域、局部熵、残差和缩放等特征提取模块。与本设计直接相关的基础如下。

| 计算结果或模块 | 当前可支持的内容 | 当前实现情况 |
| --- | --- | --- |
| 梯度窗口与选中窗口 | 梯度统计、文字与梯度区域重合 | 已保存窗口结果，OCR 数值模块可读取复用 |
| 多尺度局部熵及候选掩码 | 局部熵统计、文字与熵区域重合 | 已缓存尺度结果和候选掩码，部分合并过滤仍会重复执行 |
| RGB 功率谱 | 当前频域特征及保留的其他频谱统计 | 已保存可复用的功率谱 |
| OCR 相关结果 | 文字统计、几何统计、规则匹配、跨框组合 | 不同模块的缓存和输入要求尚未完全统一 |
| OCR 数值提取入口 | 质量、几何、梯度重合、熵重合四组计算 | 已按组保存结果，但完整入口仍依次执行各组 |

现有代码说明，部分复用已经成立，但尚未形成统一的按需调度机制。例如，一个模式只需要文字面积比例时，调用完整 OCR 数值入口仍会连带执行其他计算组。

复用必须遵守计算兼容性。OCR 纯文字结果不能直接替代可靠的逐框文字关联；RGB 各通道功率谱也不能直接替代缩放模块所使用的另一种频谱。共享前需要核对输入、预处理、算法、参数及结果结构。已经实现的缓存复用属于现有基础，不能再次计为新方案带来的收益。

## 四、前置检测执行流程

1. **接收图片与读取可用结果。** 系统识别图片及计算配置，检查已有特征和中间结果。
2. **确定当前可执行的计算。** 根据已配置策略和依赖关系，选择尚未完成、且当前需要的计算步骤。
3. **计算并保存结果。** 相同输入和兼容配置下的结果保存一次，供所有相关模式使用。
4. **更新模式状态。** 每完成一个步骤，检查哪些模式已经具备判断条件，哪些仍需要继续计算。
5. **执行匹配与分流。** 模式达到既定高置信度条件后，按既定匹配处理约定进入第二步；未匹配时继续其他必要检查。
6. **进入通用候选筛选。** 所有模式均未高置信度匹配时，复用已有结果，补齐第一步所需的剩余特征。

执行失败或结果缺失不能视为条件不满足，应保留未完成状态并按系统的重试或回退方式处理。前置命中仍仅表示符合某个已知模式，需要后续隐藏状态检测和行为验证。

## 五、可视化与交互设计

### 5.1 视图组成

以计算关系图作为主视图，通过选择联动查看模式、计算步骤及其执行效果。图中区分计算节点、中间结果、特征和模式判断，避免将不同层次的信息混为一谈。

| 视图 | 主要展示内容 | 支持的操作 |
| --- | --- | --- |
| 模式与计算关系视图 | 模式使用哪些特征，特征依赖哪些计算，哪些结果已经共享 | 展开模式或特征，追踪依赖，高亮共享来源 |
| 执行安排视图 | 计算步骤的先后关系、阶段划分和模式检查位置 | 提出共享连接，调整计算块优先级，尝试分阶段执行 |
| 调整效果视图 | 调整前后哪些计算减少、增加或仅被推迟，哪些图片更早完成匹配 | 比较方案，选择变化部分并联动查看路径或样本 |

界面不要求始终展开全部计算细节。默认展示模式和主要计算组，用户选中某项特征后，再展开相关局部关系。

### 5.2 交互一：发现并检查复用关系

用户接入一个已经确定检测定义的新模式后，点击其中某个特征。系统展示其上游计算，并高亮已有模式正在使用的兼容结果。

例如，点击“文字与高梯度区域重合程度”，系统同时显示 OCR 文字区域和高梯度区域两个输入，并指出高梯度区域也用于其他模式。

用户可以提出“连接已有结果”的候选修改。系统检查兼容性；通过后，多个消费者连接到同一计算结果。已有共享关系直接显示为已共享，不重复建立或重复统计收益。

### 5.3 交互二：消除提取入口带出的无关计算

用户展开一个提取入口，查看它实际执行的计算组与当前模式真正使用的输出。

若入口连带执行了当前路径不需要的组，用户可提出改为按需调用。系统根据所有仍需检查的模式判断这些组应当立即执行、推迟执行，还是在本次匹配完成前不再需要。

例如，只使用文字几何统计的模式，不应因调用完整 OCR 数值入口而立即触发梯度和熵计算。这项调整取消的是无关的连带计算，不是删除模式要求的特征。

### 5.4 交互三：重组执行阶段与检查位置

用户可以将共享计算与模式各自的后续计算分开安排，让已具备条件的模式及时判断，而不是等待另一个模式的全部流程结束。

系统保证修改后的安排满足计算依赖，不允许消费者在输入尚未取得时执行。对于明确要求多个条件同时成立的规则，某个必要条件不成立时，可以停止该模式尚未执行的检查。对于需要完整特征输入的模型，不能任意增加提前停止条件。

停止某个模式的检查不代表图片安全，也不代表停止其他模式。任何条件分支只能使用执行到该位置已经取得的信息，不能使用图片事后确定的攻击类型。

### 5.5 交互四：检查变化并采用方案

用户完成局部调整后，系统生成候选策略，先比较其效果，不立即替换正在使用的策略。

反馈直接关联到计算图：标出哪些结果被共享、哪些步骤执行次数减少、哪些步骤只是推迟，以及哪些图片增加了计算。用户以整批图片的汇总变化为主要依据，必要时展开差异样本。

用户据此继续调整、撤销或采用方案。采用后，新图片由系统自动处理，不需要逐张人工安排。

## 六、示例：两个模式之间的执行重组

以下模式用于说明机制，不代表项目已经验证的正式检测规则。

- 模式 A 使用高梯度区域比例和局部熵特征。
- 模式 B 使用文字与高梯度区域的重合程度和文字规则。

原来的整体执行方式可能是：先完成 A 所需的梯度和局部熵计算，A 未命中后，再取得 OCR 等结果检查 B。

用户展开依赖后发现，B 使用的高梯度区域来自 A 也需要的梯度计算，不需要等待 A 的完整检测结束。于是提出以下候选安排：

```text
梯度计算 → 保存可共享的高梯度区域
                      ↓
           补齐 B 所需的 OCR 等结果
                      ↓
                  判断模式 B
                 /          \
              命中          未命中
          按约定进入第二步    补算局部熵，继续判断 A
```

如果 B 命中，可能避免本次前置检测中的局部熵计算；如果 B 未命中，则继续完成 A 所需的检查。模式本身的特征定义和判断规则均未改变。

这个例子只说明可能的收益，不说明 B 总应优先。OCR 的新增成本、不同模式的命中情况和其他模式的计算需求都会影响结果，需要对整批样本比较。

若一张图片可能同时匹配多个模式，还需遵守既定的优先级或冲突处理约定。若要求保持原有优先级，不能在更高优先级模式尚未排除时任意采用后面的命中结果；由此带来的额外计算也应计入比较。

## 七、样本与效果检查

策略探索主要使用具有足够记录的历史样本，覆盖各已知模式、正常图片和不能匹配现有模式的图片，尽量接近实际来图分布。用户不需要预先将新的混合图片按攻击类型分组。

历史记录可能因为提前命中而缺少后续模式的检查结果。比较其他执行安排之前，应补测必要的缺失结果；新加入的模式也需要在评估样本上取得对应结果，不能把未执行当作未命中。

提出策略的样本与检查最终效果的样本分开使用。检查样本可以是已有检测结果、但未参与本轮调整的另一批历史图片。首先检查计算结果和模式判定是否符合原有定义，再观察执行开销的变化。

现阶段只明确以下检查问题，具体指标和阈值后续确定：

- 是否减少实际计算，而不仅是减少界面上的步骤？
- 哪些图片受益，哪些图片增加了开销，整批处理是否更快？
- 是否维持模式判断和既定分流要求？
- 换一批图片后，收益是否仍然存在？

使用缓存结果回放时，可以估计执行次数和成本，但不能将读取历史缓存的时间当成首次处理新图片的计算时间。候选策略需要结合记录的计算成本或实际测量进行检查，并区分预计收益与实测结果。

对于最终未匹配任何模式、仍需补齐全部特征的图片，单纯改变顺序通常不会减少特征计算总量。效果评估需要包含补齐特征及调度开销。也不应仅以入口局部提速，掩盖分流变化带来的后续额外成本。

## 八、用户与系统的职责

| 用户负责的分析与决策 | 系统负责的计算与约束 |
| --- | --- |
| 理解新模式与已有计算之间的关系 | 建立和展示依赖，发现候选共享来源 |
| 定位不必要的连带计算或过早计算 | 记录执行情况，提供联动解释 |
| 提出共享连接、阶段划分与优先安排 | 检查兼容性、依赖和规则合法性，生成可执行策略 |
| 查看差异并选择保留、修改或撤销 | 回放与实测，计算整体影响，自动运行采用的策略 |

人的作用是通过可视分析提出和检查执行结构的调整，不是手工计算最佳顺序，也不是代替检测器判断每张图片。后端可以自动推荐候选方案；可视化交互是否比纯自动方案更有帮助，需要通过实际任务验证。

## 九、与 INFUSE 的关系及实现范围

INFUSE 支持联动查看特征与模型、比较不同特征选择结果，并评估用户提出的特征组合。本方案借鉴其“选择对象—联动解释—提出修改—评估反馈”的交互思路，将分析对象改为固定模式的计算依赖与执行安排。

本方案不直接采用 INFUSE 的特征排名作为执行顺序，也不在前置入口重新选择模式所需特征。计算复用、执行阶段重组和效率评估属于面向本系统的设计扩展。

实现时需要在已有缓存和分组代码基础上，补充可按需调用的计算单元、明确的输入输出与配置描述、共享结果管理、执行记录及候选策略回放。前端的连接与拖动操作必须落到这些后端能力上，不能只改变图的外观。

本报告是一份设计方案，尚未实施统一调度器或交互界面，亦未取得效率提升的实测结论。现有三步骤系统和已确定的 PPT 版本不因此自动变更。
